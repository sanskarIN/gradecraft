# Cross-platform support

GradeCraft uses one React/TypeScript application for every target. The browser build remains a progressive web app, while Tauri 2 provides native application shells for desktop and mobile platforms.

## Supported targets

| Target | Runtime | Development host | Release form |
| --- | --- | --- | --- |
| Web/PWA | Modern browser | Windows, macOS, Linux, ChromeOS, Android, iOS/iPadOS | `dist/` static PWA |
| Windows | Tauri + WebView2 | Windows | Native Windows bundles generated by Tauri |
| macOS | Tauri + WKWebView | macOS | `.app` and configured macOS bundles |
| Linux | Tauri + WebKitGTK | Linux | Linux bundles supported by Tauri on the build distribution |
| Android | Tauri + Android System WebView | Windows, macOS, or Linux with Android tooling | APK and AAB |
| iOS/iPadOS | Tauri + WKWebView | macOS with Xcode | Xcode/iOS application build suitable for signing and distribution |

Native packages and the PWA share the same domain rules, state model, localization, accessibility behavior, storage schema, backup format, CSV format, and tests.

## Common prerequisites

Every target needs:

- Node.js 20.19 or newer
- npm
- Rust stable through `rustup` for native targets
- the platform-specific Tauri system dependencies described below

Install JavaScript dependencies once:

```bash
npm install
```

Run the platform-independent quality gate before native packaging:

```bash
npm run verify
npm run test:e2e
npm audit --audit-level=high
```

## Web and PWA

Development:

```bash
npm run dev
```

Production build:

```bash
npm run build
```

Output:

```text
dist/
```

The production browser build registers the service worker on HTTP/HTTPS origins. Packaged native applications intentionally skip service-worker registration because their frontend is already bundled with the application.

## Desktop prerequisites

### Windows

Install:

1. Microsoft C++ Build Tools with **Desktop development with C++**.
2. Microsoft Edge WebView2 Runtime when it is not already present.
3. Rust with an MSVC host toolchain.

For MSI packaging, Windows may also require the VBSCRIPT optional Windows feature.

### macOS

Install Xcode. If only desktop macOS development is needed, Xcode Command Line Tools can be sufficient for the base desktop toolchain, but full Xcode is required for iOS work.

### Linux

On Debian/Ubuntu, install Tauri's WebKitGTK and native build dependencies:

```bash
sudo apt update
sudo apt install libwebkit2gtk-4.1-dev \
  build-essential \
  curl \
  wget \
  file \
  libxdo-dev \
  libssl-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev
```

Other distributions need their equivalent WebKitGTK 4.1, compiler, OpenSSL, app-indicator, SVG, and X11 development packages.

## Desktop development and builds

Run the native desktop application:

```bash
npm run native:dev
```

Compile-check the Rust/native layer without creating an installer:

```bash
npm run native:check
```

Build a native desktop release for the operating system currently running the command:

```bash
npm run native:build
```

Tauri places desktop bundle output below:

```text
src-tauri/target/release/bundle/
```

A desktop operating system should normally build its own release packages. For example, create Windows installers on Windows and macOS bundles on macOS.

## Android prerequisites

Install Android Studio and use its SDK Manager to install:

- Android SDK Platform
- Android SDK Platform-Tools
- NDK (Side by side)
- Android SDK Build-Tools
- Android SDK Command-line Tools

Set `JAVA_HOME` to the Java runtime used by Android Studio, set `ANDROID_HOME` to the Android SDK, and set `NDK_HOME` to the selected NDK installation.

GradeCraft's Tauri configuration currently sets Android minimum SDK level 24.

## Android initialization and development

Initialize the generated Android project once per fresh checkout or after intentionally deleting the generated Android project:

```bash
npm run android:init
```

Run on a connected device or emulator:

```bash
npm run android:dev
```

Open Android Studio through Tauri when IDE-level debugging is useful:

```bash
npm run android:dev -- --open
```

## Android release packages

Build an APK:

```bash
npm run android:build -- --apk
```

Build an Android App Bundle for Google Play distribution:

```bash
npm run android:build -- --aab
```

Release publication requires an Android signing key and store configuration. Signing secrets must never be committed to this repository.

## iOS and iPadOS prerequisites

iOS development requires macOS with full Xcode installed and initialized. Physical-device and App Store distribution also require the appropriate Apple developer signing configuration.

GradeCraft's Tauri configuration currently sets iOS minimum system version 14.0.

## iOS initialization and development

Initialize the generated Apple project:

```bash
npm run ios:init
```

Run on an available simulator/device:

```bash
npm run ios:dev
```

Open the generated project in Xcode through Tauri:

```bash
npm run ios:dev -- --open
```

For physical-device development, expose the Vite development server through Tauri's host option:

```bash
npm run ios:dev -- --host
```

`vite.config.ts` reads `TAURI_DEV_HOST`, so the same frontend development server can be reached from a device on the local network.

## iOS release build

Create the iOS release build:

```bash
npm run ios:build
```

Final device/App Store packaging is governed by Apple's signing, provisioning, entitlements, and App Store requirements. Do not put signing certificates or provisioning secrets in Git.

## Application icons

The canonical icon source remains:

```text
public/icons/icon.svg
```

Generate Tauri's platform icon set manually with:

```bash
npm run native:icons
```

The native development, initialization, and build scripts already run this command automatically, so the SVG remains the single source of truth.

## Native file exports

Browser builds continue to use a standard browser download. Native builds open Tauri's system save dialog first.

- Windows, macOS, Linux, iOS/iPadOS, and ordinary native filesystem paths are written through Tauri's filesystem plugin.
- Android document providers can return `content://` destinations instead of ordinary paths. GradeCraft detects those destinations and routes the text through `src-tauri/src/android_export.rs`, which writes through Android's `ContentResolver` output stream in truncate/write mode.

The Android-specific adapter exists only at the platform boundary; JSON backup, encrypted-backup, and CSV contents remain generated by the same shared TypeScript code used everywhere else.

The capability in `src-tauri/capabilities/default.json` is local to the `main` window and grants only core defaults, native dialog access, and file-write commands needed for user-requested exports. GradeCraft does not expose remote web content to these native capabilities.

## Local data and privacy

GradeCraft remains client-only on every platform. Course and settings data stay in the local WebView storage associated with the installed application. There is no GradeCraft account or required server. JSON, encrypted JSON, and CSV portability formats remain compatible between the web, desktop, and mobile builds.

Before uninstalling a native application or clearing its application data, export a backup if the data must be retained.

## Continuous integration

`.github/workflows/native.yml` validates:

- the Rust/Tauri core on Ubuntu, Windows, and macOS;
- Android project generation on an Android-capable Linux runner;
- iOS project generation on macOS.

Store signing is deliberately outside pull-request CI. Release credentials must be supplied only by the trusted release environment.

## Platform-specific troubleshooting

### Native command cannot find Rust

Verify:

```bash
rustc --version
cargo --version
rustup show
```

### Android command cannot find the SDK or NDK

Verify `JAVA_HOME`, `ANDROID_HOME`, and `NDK_HOME`, then restart the terminal so environment changes are visible.

### Android export creates no usable provider file

Use the current GradeCraft native build, which routes Android `content://` destinations through the native `ContentResolver` adapter. If a particular document provider still rejects the write, reproduce it with sample data and record the provider/device/Android version before changing the shared backup format.

### iOS command cannot use Xcode

Launch Xcode at least once after installation and allow it to finish installing components. Verify the active developer directory with:

```bash
xcode-select -p
```

### Linux WebKitGTK build error

Recheck the Linux system dependencies listed above. The native shell needs WebKitGTK development headers even though the React application itself is platform-independent.

### Native export dialog does not appear

Confirm that the app was launched through a Tauri native command (`native:dev`, `android:dev`, or `ios:dev`) rather than through `npm run dev`, which intentionally exercises browser behavior.

## Source layout

```text
src/                              shared React/TypeScript application
src-tauri/                        native Tauri/Rust shell
src-tauri/src/lib.rs              shared desktop/mobile Tauri runtime
src-tauri/src/main.rs             desktop executable entry point
src-tauri/src/android_export.rs   Android document-provider export adapter
src-tauri/tauri.conf.json         target and bundle configuration
src-tauri/capabilities/           native security permissions
public/                           web/PWA resources and canonical app icon
docs/platforms.md                 this platform guide
```
