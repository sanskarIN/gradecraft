# Android document-provider export boundary

GradeCraft normally saves native exports through Tauri's dialog and filesystem plugins. Android document providers may return a `content://` URI, which is a provider-managed document destination rather than an ordinary filesystem path.

For those destinations, `src/utils/download.ts` invokes the narrow `write_android_content_uri` command. The Rust implementation in `src-tauri/src/android_export.rs`:

1. Rejects destinations that do not start with `content://`.
2. Uses the Android activity's `ContentResolver`.
3. Parses the selected URI with Android's `Uri` API.
4. Opens the provider output stream in write/truncate mode.
5. Writes the already-generated GradeCraft text bytes.
6. Flushes and closes the stream.
7. Returns only success or a sanitized transport error to the frontend.

This adapter does not define or modify GradeCraft's JSON, encrypted-backup, or CSV formats. Those formats remain generated by shared TypeScript code and therefore remain portable across web, desktop, Android, and iOS/iPadOS builds.

The JNI dependency is Android-only in `src-tauri/Cargo.toml`. Desktop platforms do not compile or ship the Android JNI dependency.

## Verification

The release gate requires the adapter file, JNI dependency, and key ContentResolver operations. Native CI must additionally compile the Rust/Tauri shell and generate the Android project before the Android source target is considered release-ready.

A real Android APK/AAB publication still requires device/emulator smoke testing and protected signing credentials outside source control.
